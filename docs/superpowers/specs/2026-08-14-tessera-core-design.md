# Tessera: ядро на блоках

Спека первой рабочей версии. 14 августа 2026.

## Что делаем

Аналитику для мобильных приложений, которая живёт на сервере владельца
приложения. Разработчик скачивает один файл, запускает, задаёт пароль, ставит
SDK и размечает в коде то, что хочет мерить. Через минуту у него панель с
живыми числами и никаких чужих облаков.

Отличий от соседей по нише два, и оба принципиальные.

**Ставится одной командой.** У Aptabase на этом месте три контейнера: их
сервис, Postgres и ClickHouse. Здесь один бинарник и файл базы рядом.

**Людей по умолчанию не считаем.** Событие уходит без идентификатора вовсе,
поэтому панель работает без согласий и политик. Тумблер «считать людей»
включается осознанно, и только тогда появляются удержание, когорты и воронки по
людям.

Третье отличие вырастает из архитектуры: панель собирается из блоков, и то, что
принесёт чужой модуль, встаёт в неё наравне с тем, что рисует ядро.

## Границы первой версии

Входит: сервер приёма, хранение со сводками, панель на блоках, настраиваемый
дашборд, словарь имён, Flutter SDK, описанный протокол приёма.

Не входит (и это осознанно): каталог модулей с установкой в один клик, роли и
несколько пользователей, оповещения, конструктор воронок, сравнение приложений
между собой, выгрузка отчётов. Сами модули тоже не входят — входит договор, на
котором работает ядро, и запуск программ-модулей.

## Устройство

Четыре части в одном процессе.

**Приём.** `POST /i` принимает пачку событий, отвечает 202 сразу и кладёт их в
буфер в памяти. Раз в секунду или на каждой тысяче событий буфер уходит в базу
одной транзакцией. Клиент не ждёт записи: его дело — отдать и забыть.

**Хранение.** SQLite в режиме WAL. Сырые события живут четырнадцать суток,
дальше их подчищает уборщик. Сводки по дням живут вечно и занимают копейки:
строка на сочетание «день, вид, имя».

**Сводки по расписанию.** Раз в десять минут пересчитываются последние двое
суток, раз в сутки — всё окно. Панель ходит только в сводки. Это правило снято
с живых граблей: в админке Togetherly вкладка с расчётом на лету отвечала три
минуты, после переезда на готовые файлы — четыре миллисекунды.

**Панель.** Ванильный JS без сборки, вшит в бинарник через `embed`. Оформление
взято из принятого макета: растр, монохром, тёмная тема, адрес строки хранит
вкладку.

## Договор блоков

Сердце проекта. Панель не знает ни про доход, ни про модерацию, ни даже про
события — она умеет рисовать десять заготовок и брать к ним данные по адресу.

| Заготовка | Что рисует | Что ждёт от источника |
|---|---|---|
| `stat` | плитка: число, подпись, искра | `{value, sub, spark[]}` |
| `columns` | столбики по дням, стопкой | `{items:[{label, parts:[{v, style}]}], unit}` |
| `raster` | ряды кусочков, счётом | `{rows:[{name, value}], unit, unitLabel}` |
| `table` | таблица со строкой-полосой | `{cols[], rows[][], barCol}` |
| `map` | карта двух величин | `{points:[{name, x, y, size}], xLabel, yLabel}` |
| `funnel` | шаги с отвалом | `{steps:[{name, value, note}]}` |
| `heat` | матрица когорт | `{rowLabels[], colLabels[], cells[][]}` |
| `shelf` | лента кадров с фильтром | `{items:[{url, caption, kind, group}], total, pages, kinds[], adult, group}` |
| `search` | поле поиска и таблицы ответов | `{sections:[{title, cols[], rows[][], link}]}` |
| `list` | строки «имя — значение» | `{items:[{name, value}]}` |
| `note` | пояснение текстом | `{text}` |

Блок в раскладке описывается так:

```json
{ "type": "columns", "title": "События по дням", "span": 8,
  "src": "core:events_daily", "unit": "событий" }
```

`span` — ширина в колонках двенадцатиколоночной сетки. `src` — адрес данных
вида `<владелец>:<ключ>`: `core:events_daily` отдаёт ядро, `income:month` —
модуль «Доход». Панель одинаково не знает ни про того, ни про другого.

Лента (`shelf`) ходит за страницами сама и складывает фильтры: `page`,
`kind` (вид файла), `adult` (`only`, `hide`), `group` (одна пара). Выбранные
значения возвращаются в ответе, чтобы панель нарисовала их состояние даже
тогда, когда фильтр поставил не сам блок.

**Один блок умеет отправить другой.** Раздел таблицы вправе назвать колонку,
чьё значение является фильтром для соседа:

```json
"link": { "col": 0, "src": "moderation:shelf", "param": "group",
          "title": "Показать файлы этой пары" }
```

Панель делает такую ячейку кнопкой, кладёт значение в память названного блока
и просит его перечитать данные. Ни поиск, ни лента при этом друг о друге не
знают: связку описывает модуль, а искать блок на вкладке — дело панели.

Диапазон приходит параметром `range` и понимает три записи: `7d`, `15d`, `30d`
(последние сутки включительно), `all` и пару дат `2026-07-31..2026-08-14`.
Блок сам диапазон не хранит: его задаёт панель, одинаково для всей вкладки.

**Ядро поставляет свои блоки тем же способом.** Вкладки «Обзор», «Экраны» и
«Люди» — это раскладки из тех же заготовок, лежащие в базе. Отсюда следует
приятное: пользователь двигает блоки ядра и блоки модулей вперемешку, а
договор проверяется на себе с первого дня.

### Api панели

```
GET  /api/layout?tab=overview        раскладка вкладки: список блоков
POST /api/layout                     сохранить раскладку (перетаскивание)
GET  /api/block?src=core:events_daily&range=15d   данные одного блока
GET  /api/tabs                       вкладки: ядро плюс те, что дали модули
GET  /api/labels · POST /api/labels  словарь имён
GET  /api/modules · POST /api/modules/<id>/toggle
```

## Модули

Модуль — папка рядом с бинарником и программа внутри неё.

```
modules/income/
  module.json     манифест
  main.py         программа (любой язык, лишь бы запускалась)
```

```json
{
  "id": "income",
  "name": "Доход",
  "version": "1.0.0",
  "run": ["python3", "main.py"],
  "every": "20m",
  "tabs": [
    { "id": "income", "title": "Доход", "blocks": [
      { "type": "stat",    "title": "Доход за август", "span": 4, "src": "income:month" },
      { "type": "table",   "title": "Источники",       "span": 8, "src": "income:sources" },
      { "type": "columns", "title": "По месяцам",      "span": 12, "src": "income:history" }
    ]}
  ],
  "tiles": [
    { "type": "stat", "title": "Доход за месяц", "src": "income:month" }
  ]
}
```

`tiles` — блоки, которые модуль предлагает положить на «Обзор». Не кладёт сам:
решает владелец панели, добавляя их в раскладку.

**Разговор идёт через обычный вывод программы.** Ядро запускает её двумя
способами:

```
python3 main.py collect                 раз в «every», печатает {"month": {...}, "sources": {...}}
python3 main.py query sources '{"range":"30d"}'   по требованию, печатает данные одного ключа
```

Что напечатано в stdout, то ядро разбирает как JSON и кладёт в таблицу
`module_data`. Панель читает уже оттуда. Модуль не слушает портов, не держит
процесса и проверяется руками: запустил в терминале, увидел JSON.

Таймауты: минута на `collect`, пять секунд на `query`. Программа не ответила
или напечатала мусор — блок рисуется с честной надписью «модуль не ответил», а
причина ложится в журнал. Панель от этого не падает.

**Безопасность.** Модуль работает с правами процесса панели и может всё то же
самое. Это ровно та же сделка, что с плагинами Obsidian, и она должна быть
написана в интерфейсе прямым текстом: ставь то, чему доверяешь.

## Модель данных

```sql
apps(id TEXT PRIMARY KEY, name TEXT, key TEXT UNIQUE, created INTEGER)

events(rowid INTEGER PRIMARY KEY, app TEXT, eid TEXT, ts INTEGER, who TEXT,
       platform TEXT, version TEXT, kind TEXT, name TEXT, ms INTEGER, params TEXT)
  INDEX (app, ts), (app, kind, name, ts), UNIQUE (app, eid)

daily(app TEXT, day TEXT, kind TEXT, name TEXT,
      hits INTEGER, people INTEGER, ms INTEGER, PRIMARY KEY (app, day, kind, name))

seen(app TEXT, day TEXT, who TEXT, PRIMARY KEY (app, day, who))   -- для уникальных, живёт 90 дней

layout(tab TEXT PRIMARY KEY, blocks TEXT, updated INTEGER)
labels(app TEXT, key TEXT, title TEXT, PRIMARY KEY (app, key))
module_data(module TEXT, key TEXT, json TEXT, updated INTEGER, PRIMARY KEY (module, key))
settings(k TEXT PRIMARY KEY, v TEXT)
```

`kind` — вид события: `screen`, `action`, `funnel`, `ad`. `who` — хеш, и только
при включённом счёте людей. `params` — json, но по нему не ищем: он для
просмотра одиночной записи.

## Протокол приёма

```
POST /i
X-Tessera-Key: <ключ приложения>
Content-Type: application/json
Content-Encoding: gzip (необязательно)

{ "app": "togetherly",
  "sdk": "flutter 0.4.1",
  "events": [
    { "eid": "01J...", "ts": 1786700000, "kind": "screen", "name": "memory_lane",
      "ms": 5888, "platform": "android", "version": "1.28.2+193",
      "who": "9f0c...", "params": {"tab": "photos"} }
  ] }

→ 202 { "ok": true, "received": 1 }   // разобрано событий; дубли отсеет база
```

`eid` — идентификатор события на стороне клиента; повтор с тем же `eid`
отбрасывается. Отсюда идемпотентность: телефон, потерявший ответ, шлёт пачку
заново без риска задвоить числа. Урок Togetherly: отказ «уже существует» —
это не ошибка, а подтверждение.

## Flutter SDK

```dart
await Tessera.start(
  url: 'https://tessera.мойсервер',
  key: '...',
  app: 'togetherly',
  people: false,        // по умолчанию людей не считаем
);

Tessera.screen('memory_lane');
Tessera.action('memory_added', {'kind': 'photo'});
Tessera.action('memory_added', title: 'Воспоминание добавлено');  // имя сразу в панель
Tessera.funnel('pair_created');
```

Требования, снятые с чужих ошибок: буфер на диске и отправка пачками (метро и
лифт не должны съедать статистику); ни одного модального шага до первого кадра
(на этом Togetherly ловил белый экран запуска на iOS); никаких сторонних
зависимостей и вес в сотни килобайт (APK и так худел с 80 до 45 мегабайт).

## Приватность

Выключенный тумблер: поле `who` не заполняется вовсе, в базе только счётчики.

Включённый: SDK хранит `installId` (uuid, заводится один раз) и шлёт его,
сервер считает `sha256(соль + installId)` и хранит только хеш. Соль лежит в
`data/.salt`, наружу не отдаётся никогда. Хеши в `seen` живут 90 дней, дальше
уборщик их сносит, а сводки остаются.

Юрисдикция владельца проекта — Молдова: закон 133/2011 и GDPR, а не 152-ФЗ.

## Установка и работа

```
./tessera --data ./data --port 8090
```

Первый запуск спрашивает пароль и печатает ключ приложения. Дальше панель на
`http://сервер:8090`, вход по паролю, кука на неделю.

Обновление: заменить файл и перезапустить. Схема базы обновляется сама, вперёд
и только аддитивно.

## Проверка

`go test ./...` — приём и дедупликация, пересчёт сводок, разбор манифеста
модуля, таймаут и мусор в ответе модуля, договор блоков (каждая заготовка
получает ровно те поля, что обещает).

Панель проверяется живым браузером: скрипт снимает все вкладки в двух темах и
на ширине телефона, ловит ошибки консоли и горизонтальную прокрутку. Готовый
скрипт уже написан для макета, переезжает как есть.

Живой прогон приёма: скрипт шлёт сто тысяч событий и меряет, сколько заняли
запись и пересчёт сводок.

## Чего опасаемся

**Сводки разойдутся с сырыми событиями.** Лечится тем, что пересчёт
идемпотентен: он переписывает день целиком, а не прибавляет.

**Модуль подвесит панель.** Лечится таймаутом и тем, что модуль — отдельный
процесс, а не код внутри ядра.

**База распухнет.** Четырнадцать дней сырых событий при нагрузке Togetherly —
это 365 МБ. Настраивается флагом, сводки не растут.

## Имена (проверено 14 августа 2026)

Пакет Flutter — **`tessera`**, на pub.dev свободен. Домен — **`tessera.sh`**,
свободен, и зона читается как shell: `curl -sL tessera.sh | sh`. Короткие
`.dev`, `.app`, `.run`, `.host`, `.tools`, `.systems`, `.zone` и
`gettessera.com` заняты все.

Будущий пакет JS — **`tessera-analytics`**: просто `tessera` в npm занят.

Имя на pub.dev занимается публикацией, а не бронью, поэтому пустой пакет
0.0.1 стоит выложить вместе с первым рабочим SDK.
